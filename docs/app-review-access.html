App Review Access

Congregation Scheduler · org.jwscheduler.congregation_scheduler
Access instructions for Google Play and App Store reviewers.

Why the app asks you to connect first

This app is self-hosted and has no central server. Every congregation keeps its data in its own separate Google Firebase project, and the app is not compiled against any one of them. So on first launch it shows a “Connect to your congregation” screen and asks which database to use. Until that is done there is no account system to sign in to.

A demo congregation is provided below for review purposes.

If the app opens directly on the “Sign in” screen, do step 1 first. That means the app is still connected to a configuration from an earlier installation, and a sign-in attempt will fail with “API key not valid” no matter which credentials are used.

Steps

  1. If the app opens on Sign in, tap Change configuration at the bottom of that screen. If it opens on Connect to your congregation, go straight to step 2.
  2. Connect the app to the demo congregation, either way below: tap Scan QR code and scan the code in the next section, or paste the configuration text into the input field on that screen.
  3. If the app answers “Configuration saved. Close and reopen the app to apply it.”, then fully close the app — swipe it away from the recent-apps list, or use Force stop — and open it again. Returning to the previous screen is not enough: the app keeps using the old database until it restarts. This message only appears when a configuration was already present.
  4. Sign in with the e-mail address and password supplied in the store's review-credentials section (Google Play Console → App access, or App Store Connect → Sign-in information). No 2-step verification and no one-time code is required, and the account does not expire.

If sign-in reports “API key not valid”

That message means the app is pointed at the wrong database. It is not a problem with the e-mail address or password — those are checked only after the app has reached the right project. It happens when the configuration the app is holding is not the one above, usually because a configuration from an earlier installation is still stored, or because the configuration text was mistyped.

To resolve it, repeat steps 1–3, taking care to fully close and reopen the app at step 3.

This configuration is not a secret. It only identifies which Firebase project the app talks to. The data inside is protected by that project's own server-side security rules, which reject every request that does not come from a signed-in, verified member of that congregation. Publishing it here is the same information a congregation administrator hands to their own members.
