# Screenshot captions

Headings and descriptions to paste into the caption fields of a
screenshot-framing tool (e.g. https://appshots.appstate.xyz/). One block
per screenshot, in the order they should appear in the store listing.

The screens themselves are listed in [SHOT-LIST.md](SHOT-LIST.md) — this
file is only the text that goes *around* the screenshot in the frame.

## How to use these

- **Heading** is the big line. Keep it on one or two lines; if the tool
  wraps it to three, use the **short heading** instead.
- **Description** is the small line underneath. If your template has no
  second line, drop it — every heading stands on its own.
- Use the same font, colour and text position on all frames. Mixed
  layouts across a carousel read as unfinished more than any single
  frame's wording does.
- Screenshots 1–3 are the ones most people ever see (Play shows ~3 above
  the fold, the App Store 2–3), so the self-hosting pitch, the personal
  overview and the midweek meeting go first.
- Copy the text only from inside the code fences.
- Lengths as written: headings 29–43 characters, short headings 19–31,
  descriptions 98–136. Neither store limits caption text (it's baked into
  the image), so these are layout limits, not policy ones.

## Consistency notes

- Hyphens above are plain `-`, matching the store descriptions, which
  avoid em dashes because both consoles' text fields render them
  inconsistently across platforms.
- Nothing here claims any affiliation with the Watch Tower Bible and
  Tract Society. Keep it that way in any caption you rewrite - the
  listing carries an explicit non-affiliation line and the screenshots
  must not contradict it.
- Screenshots must be captured from a demo project with placeholder
  names. If a caption tempts you to show real data ("see who has waited
  longest"), fake the data, not the caption.
